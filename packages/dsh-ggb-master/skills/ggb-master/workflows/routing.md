# routing —— Generate / Modify 选路

进入本 skill 后第一件事是选路。判断依据只有一条：**我们手里有没有可供修改的、用户认可的 .ggb**。

## 决策树

```
用户给了一个 .ggb 文件 / 引用了 projects/ 里已有课件 / 说"改一下之前的"？
├─ 是 → Modify（读入 .ggb → 解包 → 补丁 XML → 校验 → 重打包）
└─ 否 → Generate（需求 → design.md → 确认 → 手写 XML → 校验 → 打包）
```

### 该选 Generate 的场景

- 用户描述一个现象/规律，想要一个能**探究**的课件。
- 用户说"做一个 XX 的模拟"，手里没有现成文件。
- 用户带了素材（题目、知识点、数学公式），但没给 .ggb。

### 该选 Modify 的场景

- 用户给了 `.ggb`，想调参数、加对象、改交互、换文字。
- 用户说"沿用之前的课件，把 XXX 改一下"。

### 边界情况

- **用户给了 .ggb 但想让结构重来**：先走 Modify 的解包理解，如果结论是重构面超过 60%，问一句是否重建（转 Generate，以原 .ggb 为参考素材）。
- **需求没说清走哪条**：默认 Generate；流程内的 Planner 阶段会负责把需求问清楚。
- **用户提到"网上/别人做过类似的演示"**：问一句能不能拿到那个 .ggb——拿到走 Modify（或
  借鉴其构造、解包看关键 XML），只拿到截图/视频就当作题材参考走 Generate。

## 选路后的入口

| 路线 | 下一步 |
|---|---|
| Generate | 读 `generate-ggb.md` |
| Modify | 读 `modify-ggb.md` |

## quick 模式（跳过确认门）

用户在**开始时**明确表达以下意图之一 → 本次运行跳过流程第 4 步确认门，直接进 Builder：

- 「quick」「快速出」「直接做」「不用确认」「别问我」
- 「先出一版看看」「随便做一版」

规则：
1. 只跳过**确认门**；需求理解、design.md、五层校验、打包一步不少。
2. 在 design.md 顶部标注 `> 确认：quick 跳过（<用户原话>）`，决策留上下文。
3. 中途出现实质分歧（题材二选一、物理模型不确定）仍要问——quick 不等于瞎猜。
4. 用户没说 quick → 默认走完整确认门。

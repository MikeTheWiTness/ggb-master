# planner —— design.md 怎么写

> 规划角色。design.md 是 Generate 路线的唯一规划工件：
> 确认门的展示对象、跨会话续做的依据、Modify 理解原意图的入口。
> 写完交给流程第 4 步做单阶段确认。

## 0. 输入

需求事实单（流程第 1 步产出）+ 题型手册（templates/，按题型选读）+ 参考样例解剖。

## 1. 结构（对应 project_manager 生成的模板）

| 小节 | 内容 | 验收标准 |
|---|---|---|
| 探究目标 | 一段话：观众拖什么/按什么、看到什么、得出什么结论 | 说得出「玩前不懂 → 玩后会了」 |
| 参数滑杆清单 | 表：label/含义/范围/初值/步长/动画 | **每个物理量一个滑杆**，公式里不写死任何可直接调参的数值 |
| 模型有效域 | 解析解成立条件 + 最坏参数组合推导（design-rules.md §1/§2） | 滑杆拉到两头不出鬼：无负长度、无互穿、无定义域越界 |
| 演示机制 | 主时钟、按钮、复选框、动态读数 | 观众层一键到底，开箱可演 |
| 画面布局与文字 | 坐标系、像素布局、全部 caption/文本内容 | 中文文案在这里定稿，Builder 照抄 |

## 2. 纪律

1. **数学先行**：先把「状态 = 时间的显式函数」写出来（含公式），再谈界面。物理真实性红线：
   - 只做解析解系统；状态必须可写为时间的显式函数。
   - 允许级数/牛顿迭代解隐式方程（如开普勒方程），**禁止**匀速近似造假。
   - 禁止手写积分递推方案（JS/Sequence 循环累加）；内置 `NSolveODE` 许可，属于"用 GeoGebra 命令解算轨迹"的允许形态。
2. **双层交互**（用户要求）：教师层参数充分——每个物理量独立滑杆、范围给真实物理量区间；观众层简单——默认场景开箱可演、播放/暂停/重置一键按钮、读数自动更新。
3. **脚本分层预演**：在 design.md 里标注每个交互动作用 ggb 命令还是 JS 实现（命令优先：先命令，表达不了才 JS）。绝大多数情况 ggb 命令够用。
4. **一致性自检**：确认后，design.md 的任何改动必须同步给 Builder；Builder 以 design.md 为唯一事实源。
5. **复杂度分级（决定是否分步构建）**：design.md 顶部标注复杂度。判据出现任一即「高」：
   - 派生链（expression 依赖链）≥ 10 个对象；
   - 涉及事件/拓扑（多次穿越、分支选择、临界态，如场区边界穿越类）；
   - 闭式公式含 acos/atan2 类反函数选支。
   高复杂度 → generate-ggb.md 的**三步分步模式**（静态构图 → 参数化 → 交互打磨），
   每步独立打包给用户实测检查，禁止一次性生成完再交付。

## 3. 滑杆清单填写范例（开普勒第三定律）

| label | caption | min~max | 初值 | 步长 | 动画 |
|---|---|---|---|---|---|
| t | 时间 / 平近点角 t（动画） | 0 ~ 6.283 | 0 | 0.02 | step=0.02 speed=1 type=1(振荡) playing=false（打开不播，由按钮启动） |
| a | 半长轴 a | 2~8 | 5 | 0.1 | 静止 |
| ex | 离心率 e | 0~0.7 | 0.5 | 0.01 | 静止 |
| dt | 第二定律时间间隔 Δt | 0.1~1.0 | 0.2 | 0.05 | 静止 |

要点：主时钟只有一个（`t`），其余滑杆静止、只影响函数关系；`playing` 初始一律 false（打开不播，interactivity.md §3 教训），动画由播放按钮启动。

## 4. 确认话术（流程第 4 步）

展示摘要给用户，四件事：
1. 探究目标一句话。
2. 滑杆清单（表）。
3. 演示机制（按钮/动画怎么玩）。
4. 布局与文案（可选，太多就口头概括）。

用户说「可以」→ 进 Builder；用户说「quick 跳过」已表达过 → 直接进 Builder 并在 design.md 标注。
